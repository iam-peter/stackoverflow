## Question

A C++ `Backend` exposed with `setContextProperty()` has a `QList<QObject*>` property that is
used as a `ListView` model. The list stays empty and QML warns
`Required property name was not initialized`.

Read the full question on [Stack Overflow](https://stackoverflow.com/questions/77967427/qt6-warnings-when-qml-listview-accesses-c-model).

## My answer

I've made you an example that uses [`QML_SINGLETON`](https://doc.qt.io/qt-6/qqmlengine.html#QML_SINGLETON) to register the backend in QML and defines `DataObject` (`Item`) as a [`QML_ELEMENT`](https://doc.qt.io/qt-6/qqmlengine.html#QML_ELEMENT) so it will be made visible in QML and the properties are being exposed.

I changed from `setContextProperty` to a singleton due to the reasons explained in this [article](https://www.linkedin.com/pulse/qt-qml-hot-tips-5-mike-trahearn/).

The important thing to make `DataObject` known in `Main.qml` is to import the URI of the module the `DataObject` sources were added to (`import Demo77967427`).

The only weird part is that without "casting" the `Backend.model` to a `list<DataObject>` it doesn't work.
```qml
property list<DataObject> myModel: Backend.model
```
And then continue to use `myModel` as the model that gets bound to the `ListView`.

**main.cpp**
```cpp
...
qmlRegisterSingletonType<Backend>("FooBar", 1, 0, "Backend", [](QQmlEngine *, QJSEngine *) {
    return new Backend();
});
...
```

**dataobject.h**
```cpp
class DataObject : public QObject
{
    Q_OBJECT
    Q_PROPERTY(QString name MEMBER m_name NOTIFY nameChanged)
    QML_ELEMENT

public:
    DataObject(QObject *parent = nullptr);
    DataObject(QString name, QObject *parent = nullptr);

signals:
    void nameChanged();

private:
    QString m_name;
};
```

**backend.h**
```cpp
class Backend : public QObject
{
    Q_OBJECT
    Q_PROPERTY(QString header MEMBER m_header NOTIFY headerChanged)
    Q_PROPERTY(QList<QObject *> model MEMBER m_model NOTIFY modelChanged)
    QML_ELEMENT
    QML_SINGLETON

public:
    explicit Backend(QObject *parent = nullptr);
    virtual ~Backend() override;

signals:
    void headerChanged();
    void modelChanged();

private:
    QString m_header;
    QList<QObject *> m_model;
};
```

**Main.qml**
```qml
import QtQuick
import FooBar
import Demo77967427

Window {
    id: root
    width: 640
    height: 480
    visible: true
    title: qsTr("Hello World")

    property list<DataObject> myModel: Backend.model

    ListView {
        id: listView
        anchors.fill: parent
        anchors.margins: 20
        spacing: 10
        orientation: ListView.Vertical

        model: root.myModel

        delegate: Item {
            id: myItem
            required property string name

            width: label.width
            height: label.height
            Text {
                id: label
                text: myItem.name
                font.pointSize: 24
            }
        }

        header: Text {
            width: parent.width
            horizontalAlignment: Text.AlignHCenter
            font.pointSize: 48
            font.bold: true

            text: Backend.header
        }
    }
}
```

Have a look at the complete application [here](https://github.com/iam-peter/stackoverflow/tree/41df7a56b59c675221b6bf64134278f030a6603b/questions/77967427).

That said, the best way to expose models from C++ to QML is to derive from [`QAbstractListModel`](https://doc.qt.io/qt-6/qabstractlistmodel.html#subclassing).

----------

You shouldn't prefix your notifier with `on`, have a look [here](https://doc.qt.io/qt-6/qtqml-cppintegration-exposecppattributes.html#exposing-properties).

> Note: It is recommended that the NOTIFY signal be named
> \<property\>Changed where \<property\> is the name of the property. The
> associated property change signal handler generated by the QML engine
> will always take the form on\<Property\>Changed, regardless of the name
> of the related C++ signal, so it is recommended that the signal name
> follows this convention to avoid any confusion.

### Build and run

Requires Qt 6.5 or later with these modules: Qt Quick.

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH=~/Qt/6.x/gcc_64
cmake --build build
./build/appDemo77967427
```
