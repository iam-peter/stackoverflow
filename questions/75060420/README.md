## Question

The asker has a pure QML application with no C++ backend and no build system, and
runs `lupdate -no-obsolete` by hand. They added entries to the `.ts` files manually
for strings that are translated through a helper function, not through a literal
`qsTr()` call, and every `lupdate` run deletes those entries. They want `lupdate` to
keep them.

Read the full question on [Stack Overflow](https://stackoverflow.com/questions/75060420/how-to-prevent-lupdate-to-remove-some-entrie-from-my-translation-files).

## My answer

You could create an extra translation source (TS) file for the manual entries called `additional_locale_fr.ts` and merge it with the one generated by `lupdate`, e.g. `locale_fr.ts` by using `lconvert`.

```bash
lconvert -i additional_locale_fr.ts locale_fr.ts -o all_locale_fr.ts
```

([Merge translation files (.ts) with existing .ts files using QT Utilities (lconvert)][1])

Also interesting in this context [SO][2].

----------

You could also use `QT_TR_NOOP()` around your strings in the function. Have a look [here][3] and [here][4].

> QT_TR_NOOP is used in conjunction with the dynamic translation
> functions qsTr() and qsTranslate(). It identifies a string as
> requiring translation (so it can be identified by lupdate), but leaves
> the actual translation to the dynamic functions.

  [1]: https://stackoverflow.com/a/8527556/525038

## Code in this folder

A small app that switches between English and German at runtime and marks the
string "Apple" with `QT_TR_NOOP()`, so `lupdate` picks it up even though nothing
calls `qsTr()` on it. The build runs `lupdate` and `lrelease` and embeds the `.qm`
files, so `locale_en.ts` and `locale_de.ts` are created in this folder on the first
build. They are git-ignored.

To try the commands from the answer by hand (adjust the Qt path):

```bash
~/Qt/6.x/gcc_64/bin/lupdate . -no-obsolete -locations absolute -ts locale_en.ts locale_de.ts
~/Qt/6.x/gcc_64/bin/lrelease locale_en.ts locale_de.ts
~/Qt/6.x/gcc_64/bin/lconvert -i my_locale_de.ts locale_de.ts -o complete.ts
```

`my_locale_de.ts` stands for your own file of manual entries.
